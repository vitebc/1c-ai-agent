## Тестовая база (Windows-VM)

Что нужно на стороне VM, чтобы бэкенд дотянулся до базы:

1. 1С:Предприятие 8.3.20+.
2. Опубликованный на веб-сервере HTTP-сервис `/hs/mcp/rpc` (+ `/hs/mcp/health`)
   из форка `vladimir-kharin/1c_mcp` и нашего `A1C_Инструменты`; имя публикации
   в URL — с точным регистром (иначе редирект роняет POST в GET).
3. Пользователь 1С с read-only профилем для агента (см. AGENTS.md, «Схема запросов»).
4. Сетевой доступ с VPS до VM по HTTP(S). Основной путь — прямые вызовы бэкенда
   в `{base_url}/hs/mcp/rpc` под `ONEC_USERNAME`/`ONEC_PASSWORD` (форма сама шлёт
   `base_url`; нестандартные публикации — через `ONEC_BASES` в `.env`).
   Fallback/штатный путь без `base_url` — через MCP-прокси (адрес в `MCP_ONEC_URL`).

Проверка связности с VPS:

```bash
curl http://<vm-host>/<base>/hs/mcp/health
```

На шаге 3 сюда легли: форк `1c_mcp` (ядро MCP-протокола), наше расширение
с инструментами (`ДобавитьИнструменты`/`ВыполнитьИнструмент`, скилы `cfe-*`),
форма чата `a1c_Чат` (отправка `base_name`+`base_url`, startup-check через
`GET /tools?base_name=&base_url=`), инструкция по установке CFE в тестовую базу.
> Статус: лежит с шага 3 (см. `1c_mcp.md` «Состав нашего расширения»).
> Правила добавления обработки: запись в `Configuration.xml` (ChildObjects),
> регистрация в `mcp_КонтейнерыИнструментов` (Content), уникальные
> UUID/`TypeId`/`ValueId` — иначе «Неизвестный объект метаданных» при загрузке;
> один битый контейнер роняет весь `tools/list` ядра (там нет `Попытка`).
