# Аудит д44-44-151

Сценарий «проведи аудит d44-44-151» — сплошной контроль НСИ по 5 проверкам.
Данные берёшь **из базы 1С инструментами**, Excel/CSV у пользователя не проси.

## Порядок (нарушать нельзя)

**Шаг 0. Разведка — один раз до всех проверок.** Имена объектов и реквизитов в базе
могут отличаться от документа (в УПП это `Справочник.ДоговорыКонтрагентов`, а не
«Договоры с клиентами»). Выдумывать имена запрещено:

1. `get_configuration_info` — конфигурация, режим ИБ (заодно ответ на «что за база»).
2. `list_metadata_objects({"metaType": "Catalogs", "nameMask": "Договор"})` и
   `list_metadata_objects({"metaType": "Catalogs", "nameMask": "Контрагент"})` —
   точные имена справочников. `metaType` обязателен, значения — строго из его описания
   (`Catalogs`, `Documents`, `InformationRegisters`, `AccumulationRegisters`, ...);
   голое `Registers` не существует.
3. `get_metadata_structure({"metaType": "Catalogs", "name": "<имя>"})` по каждому
   найденному — **оба параметра обязательны**. Смотри секцию `fields` на предмет
   реквизитов: менеджер, рабочее наименование, состояние, срок, вид договора/контрагента.
4. `get_access_rights` — если по объекту нет чтения, сразу спроси доступ и не мучай запросами.

**Шаг 1.** Перед ПЕРВЫМ `execute_select` вызови `get_pattern({"name": "query-patterns"})`
и следуй тексту.

**Шаг 2.** Пять проверок по очереди, у каждой один `validate_query` → `execute_select`.

**Шаг 3.** Отчёт — таблицей в ответе (см. «Отчёт»).

## Правила запросов

- `execute_select` — **литералами, без `&параметров`**. Значения подставляешь в текст.
  В `ПОДОБНО "%слово%"` спецсимволы экранируй: `ПОДОБНО "%[а-я]%"`, `[%]` для `%`.
- Даты — только `ДАТА(ГГГГ,М,Д)`, строковые даты запрещены.
- Считай **в базе**, а не в голове: `ПОДСЧИТАТЬ(1)`, `КОЛИЧЕСТВО(*)`, `СУММА`, `МАКСИМУМ`.
  Для «КЗ = количество…» один запрос с агрегатом, а не выкачивание строк.
- Кап `execute_select` — 200 строк. Нужно больше — режь по периодам/партиям и считай агрегатами.
- Не более 2 фиксов на ошибку запроса: прочитал текст ошибки 1С → исправил → повторил.
  Третья ошибка на том же поле — стоп, ищи другое поле или спрашивай пользователя.

## Проверки

Каждая: цель → что делать → что считаем. Если нужного реквизита в базе нет —
**не подменяй похожим и не выдумывай**: в отчёте строка «поле отсутствует в базе».

1. **Менеджер не заполнен.** Справочник договоров, реквизит типа менеджер пустой.
   Плюс рабочее наименование содержит «Основной», состояние — действующий, срок — не
   просрочен. `КЗ = ПОДСЧИТАТЬ(1)` по этим отборам.
2. **Дубли действующих договоров.** Сгруппируй по контрагенту
   (`ГРУППИРОВАТЬ ПО Контрагент`), `КОЛИЧЕСТВО(*)` > 1, одинаковые условия = совпадение
   ключевых реквизитов (номер/дата/сумма/вид). `КЗ = число «лишних» договоров`.
3. **Вид договора.** Сверь значения реквизита с `predefined` из `get_metadata_structure`
   и с видами, реально встречающимися в базе. Некорректно = не соответствует функции
   договора. Если виды в базе другие — сверяй с фактическими, не с памятью.
4. **Вид контрагента ≠ ОПФ.** Сверь вид контрагента с ИНН/наименованием
   (`Юр. лицо` / `ИП` / `Физ. лицо` — по фактическим данным базы).
5. **Длинные наименования.** `ПОДОБНО "%индивидуальный предприниматель%"` и
   `ПОДОБНО "%открытое акционерное общество%"` в рабочем наименовании контрагентов
   (вместо ИП / ОАО). `КЗ = ПОДСЧИТАТЬ(1)` по каждой подстроке, суммируй.

## Отчёт

Единый отчёт **в ответе чата**, Markdown-таблица (форма отрендерит его сама):

| № | Проверка | Что смотрели | КЗ | Комментарий |
|---|---|---|---|---|

Ниже — блок «Найденные нарушения» (первые 10 строк на проверку: объект, контрагент,
номер, дата, что не так) и блок «Рекомендации» (по 2–3 конкретных действия на пункт).

КЗ = сумма по таблице. Если по проверке не было данных (нет прав/поля) — строка в таблице
со значением «—» и причиной, молча её не пропускай.

**Файлы не создаются.** Никакого `audit_nsi_report_ka2.md` — агент пишет только текст
в ответе. Пользователь скопирует таблицу сам.

## Ошибки

- `Недостаточно прав для работы с таблицей` — RLS, не подменяй объект и не повторяй
  запрос. В отчёте: «нет доступа, требуется роль с правом Чтение на <объект>».
- `Поле не найдено "X"` — вернись в `get_metadata_structure` за настоящим именем
  реквизита, а не перебирай похожие поля подряд.
- Пустой результат — так и напиши «нарушений не найдено», это валидный результат.

## Чего не делать

- Не писать запросы в предположении о именах метаданных — только из разведки шага 0.
- Не выкачивать hundreds строк ради подсчёта — агрегат в базе.
- Не выдавать `КЗ` по проверке, которую не удалось выполнить.
- Не повторять одну и ту же проверку с разными `nameMask` «на всякий случай».
