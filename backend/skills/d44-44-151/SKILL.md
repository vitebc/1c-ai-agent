# Аудит д44-44-151

Сценарий «проведи аудит d44-44-151» — сплошной контроль НСИ по 5 проверкам.
Данные берёшь **из базы 1С инструментами**, Excel/CSV у пользователя не проси.

## Синтаксис запросов 1С (проверено на живой базе, КА 2.5)

Это главный источник ошибок. Держись этих форм — остальное платформа не ест.

- **`ПЕРВЫЕ` — только сразу после `ВЫБРАТЬ`**, не после имени таблицы.
  `ВЫБРАТЬ ПЕРВЫЕ 10 Поле ИЗ Таблица` — да. `ВЫБРАТЬ Поле ИЗ Таблица ПЕРВЫЕ 10` — ошибка.
- **Подсчёт строк — `СУММА(1)`, не `СЧЁТЧИК`/`ПОДСЧИТАТЬ`.** В этой базе `СЧЁТЧИК(*)`
  и `ПОДСЧИТАТЬ(1)` дают синтаксическую ошибку. Работает:
  `ВЫБРАТЬ СУММА(1) КАК КЗ ИЗ Таблица ГДЕ <отбор>`.
- **Группировка — `СГРУППИРОВАТЬ ПО` (с буквой С).** Буква «С» обязательна.
  `ВЫБРАТЬ Статус, СУММА(1) КАК КЗ ИЗ Таблица СГРУППИРОВАТЬ ПО Статус
  УПОРЯДОЧИТЬ ПО КЗ УБЫВ` — да. `ГРУППИРОВАТЬ` без «С» — ошибка.
- **Переводы строк и табуляция разрешены** — запрос можно писать в несколько строк.
- **Незаполненное поле — `ГДЕ <Поле> ЕСТЬ NULL`** (поле есть, но пустое).
  `ЕСТЬ НЕОПРЕДЕЛЕНО` платформа не понимает.
- **Поля-перечисления (`Статус`, `ТипДоговора`) строкой не фильтруются.**
  `ГДЕ Статус = "Действует"` вернёт пусто, а полное имя
  `Перечисления.СтатусыДоговоровКонтрагентов.Действует` — ошибку «Поле не найдено».
  Единственный рабочий способ: **`СГРУППИРОВАТЬ ПО <Поле>`** и взять нужную группу
  из результата. Планируй проверки сразу через группировку, а не через `ГДЕ` по статусу.
- **Даты — `ДАТАВРЕМЯ(ГГГГ,М,Д)` или `ДАТА(ГГГГ,М,Д)`,** строковые даты запрещены.
- `&параметры` в `execute_select` не поддерживаются — `execute_query` поддерживает,
  но строковое значение перечисления он тоже не подставит. Делай литералами.
- Спецсимволы в `ПОДОБНО "%слово%"` экранируй: `ПОДОБНО "%[а-я]%"`, `[%]` вместо `%`.

## Реальные имена в этой базе (проверено, КА 2.5.22)

- Справочники: **`Справочник.ДоговорыКонтрагентов`** (синоним «Договоры с контрагентами»),
  **`Справочник.Контрагенты`**.
- **Есть:** `Менеджер`, `Статус` (перечисление: Действует / Закрыт),
  `ТипДоговора` (Закупка / Реализация / Передача на комиссию), `ДатаОкончанияДействия`,
  `Контрагент`, `Номер`, `Дата`, `Наименование`.
- **НЕТ — не используй:** `РабочееНаименование`, `ТекущееСостояние`, `СрокДействия`,
  `ВидДоговора` (есть `ТипДоговора`), `ВидКонтрагента`.
  «Рабочее наименование» = обычный `Наименование`. «Текущее состояние» = `Статус`.
  Срок = `ДатаОкончанияДействия` (пустая дата `ДАТАВРЕМЯ(1,1,1)` = бессрочный).
- Даже если имена знаешь — сверься через `get_metadata_structure` перед запросом
  (шаг 0), базы разные.

## Порядок (нарушать нельзя)

**Шаг 0. Разведка — один раз до всех проверок.** Имена объектов и реквизитов в базе
могут отличаться от документа. Выдумывать имена запрещено:

1. `get_configuration_info` — конфигурация, режим ИБ.
2. `list_metadata_objects({"metaType": "Catalogs", "nameMask": "Договор"})` и
   `... "Контрагент"` — точные имена справочников. `metaType` обязателен, значения
   строго из его описания (`Catalogs`, `Documents`, `InformationRegisters`, ...);
   голое `Registers` не существует.
3. `get_metadata_structure({"metaType": "Catalogs", "name": "<имя>"})` по каждому —
   **оба параметра обязательны**. Смотри список реквизитов и их типы.
4. `get_access_rights` — есть ошибка в базе (см. «Ошибки»), не рассчитывай на него:
   отборы и `ГДЕ` проверяй сам фактом выполнения запроса.

**Шаг 1.** Перед ПЕРВЫМ `execute_select` вызови `get_pattern({"name": "query-patterns"})`
и следуй тексту.

**Шаг 2.** Пять проверок по очереди, у каждой `validate_query` → `execute_select`.

**Шаг 3.** Отчёт — таблицей в ответе (см. «Отчёт»).

## Проверки

Каждая: цель → запрос → что считаем. Поля, которых нет в базе, **не подменяй
и не выдумывай** — в отчёте строка «поле отсутствует в базе».

1. **Менеджер не заполнен.** `ГДЕ Менеджер ЕСТЬ NULL` плюс
   `Наименование ПОДОБНО "%Основной%"` и группировка по `Статус` («Действует»).
   `КЗ = СУММА(1)`.
2. **Дубли действующих договоров.** `СГРУППИРОВАТЬ ПО Контрагент`, `УПОРЯДОЧИТЬ ПО КЗ УБЫВ`,
   оставив группы с `КЗ > 1`. `КЗ = сумма (КЗ - 1) по таким группам`.
3. **Тип договора.** `СГРУППИРОВАТЬ ПО ТипДоговора` — получишь фактические значения
   (Закупка / Реализация / Передача на комиссию). Сравни со списком из ТЗ
   (подотчёт, аренда, агентский, прочие): значения, которых нет в базе, отметь
   как «в базе не встречаются», а не выдумывай.
4. **Вид контрагента ≠ ОПФ.** `Справочник.Контрагенты`: `СГРУППИРОВАТЬ ПО
   ЮридическоеФизическоеЛицо` и сверь с фактическими ИНН/наименованием.
   Нет реквизита «ВидКонтрагента» — бери `ЮридическоеФизическоеЛицо` и сравнение
   вида с `НаименованиеПолное`; если и этого нет — строка «поле отсутствует».
5. **Длинные наименования.** `НаименованиеПолное ПОДОБНО "%открытое акционерное
   общество%"` и `"%индивидуальный предприниматель%"` (вместо ОАО/ИП).
   `КЗ = СУММА(1)` по каждой подстроке, суммируй. Проверено — работает.

## Ошибки

- `Поле не найдено "X"` — вернись в `get_metadata_structure` за настоящим именем.
  Не перебирай похожие поля подряд.
- `Синтаксическая ошибка "ПО"` — забыта буква «С» в `СГРУППИРОВАТЬ`.
- `Синтаксическая ошибка "ПЕРВЫЕ"` — `ПЕРВЫЕ` стоит не после `ВЫБРАТЬ`.
- `Синтаксическая ошибка` на `СЧЁТЧИК`/`ПОДСЧИТАТЬ` — замени на `СУММА(1) КАК КЗ`.
- `Недостаточно прав для работы с таблицей` — RLS, не подменяй объект. В отчёте:
  «нет доступа, требуется роль с правом Чтение на <объект>».
- Пустой результат — «нарушений не найдено», это валидный результат.
- `get_access_rights` сейчас падает ошибкой конструктора — вызывай один раз,
  при ошибке просто продолжай без него.

## Чего не делать

- Не писать запросы в предположении о именах — только из разведки шага 0.
- Не фильтровать перечисления строкой и полным именем — только `СГРУППИРОВАТЬ ПО`.
- Не выкачивать сотни строк ради подсчёта — `СУММА(1)`.
- Не выдавать `КЗ` по проверке, которую не удалось выполнить.
- Не повторять одну проверку с разными `nameMask` «на всякий случай».
