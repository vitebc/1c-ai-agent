# Шаблоны запросов 1С

Правила языка запросов (нарушение = синтаксическая ошибка 1С, не чинится повторами):

1. Даты — ТОЛЬКО конструкцией `ДАТА(ГГГГ,М,Д)`. Фильтр за день:
   `Дата >= ДАТА(2026,9,18) И Дата < ДАТА(2026,9,19)`.
   Запрещено: `ДАТА('20260918')`, `ДАТА(Дата, ...)`, сравнения даты со строками.
2. Сначала `validate_query` (тот же текст с `ПЕРВЫЕ 1`), потом полный `execute_select`. Без успешной проверки полный запрос не запускать.
3. Подполя ссылок не выдумывать: `Контрагент.INN` в документе может не существовать. Смотри структуру документа И структуру справочника (`get_metadata_structure` для обоих), фильтр по ИНН — через справочник Контрагенты, затем отбор по ссылке.
4. Разведка метаданных — максимум 3 вызова, дальше пиши запрос.
5. Один запрос чинить максимум 2 раза. Третья ошибка подряд — остановиться: показать пользователю, что пробовал (текст запроса + текст ошибки 1С), и спросить уточнение.
6. В `ПОДОБНО` спецсимволы `%` и `_` экранируй как `[%]` и `[_]`; параметры `&` не поддерживаются — только литералы.
7. Контрагента не ищи трижды широким поиском: первое точное совпадение по `name` из `get_counterparty` — это он, дальше работай со ссылкой.

Пример:
- Вопрос: «продажи по контрагенту ЭКСПРЕСС ОФИС за 18.09.2026»
- Действия: `get_counterparty({"query": "ЭКСПРЕСС ОФИС"})` → точное совпадение по `name` (не широкий поиск заново) → `validate_query` с `ГДЕ Контрагент = <ссылка> И Дата >= ДАТА(2026,9,18) И Дата < ДАТА(2026,9,19)` → `execute_select` тем же текстом без `ПЕРВЫЕ 1`.
